入口：`Test_Real.py`。本次仅完成代码、文件存在性检查和小型逻辑检查，未用真实数据运行模型。

在原有 WSL Lego 环境、仓库根目录执行预检查：

```bash
python EvalModel/EvalDataset/Test_Real.py
```

这个命令不导入模型依赖、不读 NPZ、不载入权重、不写实验结果，只检查路径并打印配置。可用 --data-dir 指定转换数据目录。

准备正式运行时（本次尚未执行），加 `--run`。建议首先只选择 Kosarak 和一个预算检查实际显存：

```bash
python EvalModel/EvalDataset/Test_Real.py --datasets kosarak --budgets-kib 300 --run
```

默认三个真实数据集、两个官方预训练 checkpoint、300 到 2100 KiB（步长 300）、每个组合三次完整重建写入和查询，第一次作为预热不进入汇总；预算和重复数均可通过参数改变。没有自行训练。支持 --models、--device、--hash random/cuda、--output-dir 和 --no-plots。

默认 random 与 Test_Lego 的默认行为一致，保留其批依赖哈希，故仅支持完整单批写入和同一完整 Item 集查询，不能据此宣称支持任意流式更新/子集查询。CUDA 模式是单独可选实验条件，未在本次运行验证；其依赖和数值正确性仍须在首次正式运行前的检查中确认。不可混合比较不同 hash 模式的结果。

保持原 Cluster 的预测选择：先 min(Decoder,CM)，预测不同 Item 数>10000 且 alpha<1 时选择 Decoder，否则 CM。不引入新架构或调整权重。读取量较大，未擅自拆分写入批次，因为随机哈希会因此改变语义。

原 Cluster 增加两处边界修复：clear 同时清空总权重统计；查询跳过空分块。覆盖标记校验改为一次张量归约，避免逐 Item 的 Python/GPU 同步。其他算法计算保持原样。

## 结果解释

每次运行创建独立时间戳目录 RealResults/<timestamp>：
- manifest.json：参数、版本、GPU、权重/代码/数据 SHA256、转换记录、成功或失败状态。
- runs.csv：每个数据集×预算×checkpoint×重复的 Lego 和加权 CM 读头误差。
- summary.csv：排除预热后先按 checkpoint 汇总，再计算 checkpoint 均值及总体标准差（ddof=0）。重复计时不当作新增训练种子。
- 每个数据集的 AAE/ARE/MSE 图，不需要额外 MS 文件。

AAE=平均绝对误差，ARE=平均绝对相对误差，MSE=平均平方误差。全部查询为已出现 Item，等权统计。ASE 含义尚未确认，因此没有擅自命名。

write_seconds 为所有不同 Item 的加权写入耗时；query_seconds 为完整查询耗时，包含原选择规则。CUDA 同步后按墙钟计时，排除数据加载、模型加载、Cluster 构建/clear，首轮排除编译/预热影响。吞吐分别为不同 Item 数/写入秒数、查询 Item 数/查询秒数，不是逐包/逐 token 事件吞吐。CM 读头结果来自同一次 Lego 查询；其行中的计时也是整个 Lego 流程的计时，不能解读为独立传统 CMS 的速度。

requested_kib 是请求计数内存；actual_counter_kib 是按 brick 向下取整后的实际计数内存。模型参数、额外统计和中间数据不计入这个预算；peak_allocated_bytes 另记 PyTorch 已分配显存峰值，不代表整个进程/CuPy 的显存总峰值。

没有运行 ES、传统 CMS/CS/LCS 或 MS。weighted_CM_readhead 是同一学习 embedding 的加权 CM 读头，不等同独立标准 CMS。后续与 RatioSketch 的公平比较协议仍需另行对齐。
# 自定义 NPZ 入口（2026-10-29）

在项目根目录运行 `python EvalModel/EvalDataset/Test_Real.py --npz "/mnt/d/科研/数据集/processed/kosarak.npz" --budgets-kib 300 400 500 600 700 800 --save-predictions --run`。无需注册名称。`--npz` 后可指定多个文件，不可同时使用 `--datasets`；文件名去扩展名作为结果名称，多个文件名须不同。不加 `--run` 检查文件和格式，不执行推理。

输入须包含一维 `items`（int64、严格递增且唯一）与同形状 `freqs`（正整数频率），允许额外字段。文件内全部 Item 原样用于评估，不自动切半。完整数据与半段数据由指定文件决定。原简称命令继续有效。
